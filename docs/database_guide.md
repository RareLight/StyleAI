# StyleAI Database Integration Guide

This document provides technical instructions for integrating with the two core databases used by the StyleAI ecosystem. It is intended to help other AI agents or external Python scripts securely read and interpret our image, face, and style data.

> [!CAUTION]
> **READ-ONLY ACCESS REQUIRED**
> External tools and scripts **MUST NEVER** write, update, or delete records in these databases. Database population and schema migrations are strictly managed by the StyleAI Lightroom Plugin and its backend orchestration. Writing data directly will cause catalog sync corruption and orphan records. Treat these endpoints as strictly read-only.

---

## 1. Vector Store: ChromaDB

ChromaDB is our core vector database. It stores the semantic visual embeddings of all indexed photos, text-based semantic metadata, and face recognition templates.

### Location & Setup
- **Directory Format:** The database exists as a standard ChromaDB persistent directory, typically passed as an environment variable (e.g., `/data/db` in Docker or `~/.gemini/antigravity/StyleAI/db` locally).
- **Library Requirements:** Use the official `chromadb` Python package.
- **Client Initialization:** Connect using the `PersistentClient` in read-only setups where possible.

### Collections Overview

#### A. `image_embeddings`
- **Purpose:** Stores SigLIP2 embeddings (visual representation) for similarity matching.
- **`id`:** The stable `photo_id` string generated by the Lightroom plugin.
- **`metadatas`:** Contains crucial properties:
  - `catalog_ids`: A serialized JSON list of strings representing the Lightroom catalog UUIDs this photo belongs to.
  - `uuid`: Legacy UUID field for older records.
  - Exposure metrics, keywords, EXIF data, and semantic tags.

#### B. `image_embeddings_vertex`
- **Purpose:** Stores Vertex AI Multimodal Embeddings (1408 dimensions) for highly specific text-to-image semantic search.

#### C. `face_embeddings`
- **Purpose:** Stores InsightFace templates (512 dimensions) for clustering and facial recognition.
- **`metadatas`:** Contains `photo_id` to link the face back to its source image, and `person_id` (e.g. `person_1`) representing the merged identity cluster.

### Python Integration Example

```python
import chromadb
from chromadb.config import Settings

# 1. Initialize the Persistent Client
# Ensure no telemetry is sent and connect to the existing directory
client = chromadb.PersistentClient(
    path="/path/to/styleai/db", 
    settings=Settings(anonymized_telemetry=False)
)

# 2. Access the desired collection
# Do not use get_or_create to enforce read-only safety if the DB is missing
try:
    image_collection = client.get_collection(name="image_embeddings")
except ValueError:
    print("Collection does not exist or database path is invalid.")

# 3. Querying Example: Fetch metadata for a specific photo
photo_id = "meta1:5f5a69703d800be091d61a104e25dccf"
result = image_collection.get(
    ids=[photo_id],
    include=["metadatas"]
)

if result and result.get("metadatas"):
    metadata = result["metadatas"][0]
    print(f"Catalog IDs: {metadata.get('catalog_ids')}")
    print(f"Keywords: {metadata.get('keywords')}")

# 4. Semantic Search Example (requires pre-computed text embeddings)
```

## 2. Relational Store: `styles.sqlite`

The `styles.sqlite` database stores the Auto-Discovered Style Profiles. When a photographer indexes their catalog, the backend clusters their past edits into cohesive "Styles" based on camera model and lighting conditions.

### Location & Setup
- **File Name:** `styles.sqlite`
- **Location:** Resides in the root of the ChromaDB path (e.g. `/path/to/styleai/db/styles.sqlite`).
- **Library Requirements:** Standard Python `sqlite3` library.

### Schema Overview

#### A. `styles` Table
Contains the aggregated mathematical model of a specific editing style.
- `style_id` (TEXT PRIMARY KEY): Unique identifier.
- `style_name` (TEXT): Human-readable name.
- `camera_make`, `camera_model`, `camera_profile` (TEXT): The equipment constraints.
- `genre` / `subgenre` (TEXT): The type of photography (e.g. `wedding`, `portrait`).
- `mean_exposure_dna` (TEXT/JSON): The average lighting histogram of the training examples.
- `develop_variance` (TEXT/JSON): Tracks which Lightroom sliders the photographer changes dynamically vs keeps static.

#### B. `style_examples` Table
A junction table linking a `style_id` to the `photo_id`s in ChromaDB that were used to train this style.
- `style_id` (TEXT)
- `photo_id` (TEXT)

### Python Integration Example

```python
import sqlite3
import json
import os

db_file = "/path/to/styleai/db/styles.sqlite"

if not os.path.isfile(db_file):
    raise FileNotFoundError("styles.sqlite not found")

# 1. Open read-only connection
# URIs require sqlite3 compiled with URI support
uri = f"file:{db_file}?mode=ro"
conn = sqlite3.connect(uri, uri=True)
conn.row_factory = sqlite3.Row

try:
    cursor = conn.cursor()
    
    # 2. Querying Example: Fetch all styles for a specific camera
    cursor.execute(
        "SELECT style_id, style_name, example_count, mean_exposure_dna FROM styles WHERE camera_model = ?",
        ("NIKON Z 6_2",)
    )
    
    for row in cursor.fetchall():
        print(f"Style: {row['style_name']} ({row['example_count']} photos)")
        
        # JSON fields must be parsed manually
        if row['mean_exposure_dna']:
            dna = json.loads(row['mean_exposure_dna'])
            print(f"  Mean Luminance: {dna.get('exp_luminance_mean')}")
            
except sqlite3.Error as e:
    print(f"Database error: {e}")
finally:
    conn.close()
```
